How it works

One description, proved by Lean, produces the program. This page follows it from a sentence to a running app.

Vera Security reviewer

“What is signed, what is proved, and what does my policy accept?”

Explanation: read it end to end, away from the keyboard.

Each step

Each step 7 entries
Sentence
Describe what the app decides. On the agent path, ask something like “Build me a Prism app that decides whether a payment is approved.”
Spec
Purpose, fields, outcomes, ordered rules, properties and examples. Read the properties most carefully: they are the only part that is proved.
LexLean model
Prism writes the spec as a model in LexLean. The proof and the program both come from it. So a proof about the model is a proof about what runs.
Proofs and program
Each property becomes a theorem the Lean kernel checks. The program is a WebAssembly guest with no imports: no clock, randomness, network or files.
.holo file
One file with the program, the model, its build record, its permissions and a browser view. Its BLAKE3 fingerprint names it.
Verify
Three questions. Are these the sealed bytes? Who signed what? Is that evidence enough to run it here?
Run or share
Run one request, serve the view on a port, or push to a registry. A pull writes nothing until the checks pass.

Evidence levels

Before an app runs, Prism works out how much signed evidence it carries. Only signing raises the level. Apps built today are unsigned, so they are P0.

LevelCarriesAsked for by
P0Nothing signed (bytes and examples are still verified)pull by default
P1A signed build recordthe provenance-only policy
P2Also a signed proofrun and check by default
P3Also a signed replayyour own policy file

A policy says which level is enough. To run an unsigned app on purpose, write {"minimum":"P0"} to a policy file a reviewer can see.

Where your source goes

Until the SDK image is on your machine, proofs run on the hosted verifier at mcp.uor.foundation. It stores the files under src/ unlisted. Anyone with the draft ID can read them.

Never put secrets in a model.

Words on this page 10
record
One entry in a facet: a component, a threat, a measure or a journey step, with the place in the source it came from.
LexLean
The language Prism models are written in. It reads like LaTeX and compiles to Lean 4.
Lean kernel
The small checker at the heart of the Lean prover. It accepts a proof only if every step follows the rules.
theorem
A statement about the model that the Lean kernel has checked, so it holds for every input, not only the ones tested.
holo
The app Prism builds: one signed, verified file that a browser or a device runs.
SDK
Software development kit. Here, the PrismPM container image that builds, checks and verifies Prism models.
spec
The app member of a prompt (prism/spec/1): purpose, fields, outcomes, rules, properties, examples and limits.
property
What the app must never or always answer. Each one becomes a theorem the Lean kernel proves for every request.
fingerprint
The BLAKE3 digest that names an app file. Loading recomputes it, and a mismatch refuses the file.
policy
The rule for which evidence level is enough to run an app. The default asks for P2.
